**Fixed: `test_single_decimal`** — a real bug in `pay/money.py:6`.

```
int(frac or 0)          # "0.5" -> int("5")   -> 5   ✗
int(frac.ljust(2, "0")) # "0.5" -> int("50")  -> 50  ✓
```

`to_cents` read the fraction as a literal integer instead of positionally, so any single-decimal amount was undercharged by 10x. `"0.5"` billed as 5 cents instead of 50. Verified the surrounding cases still hold: `12.34`→1234, `7`→700, `0.05`→5, `10.00`→1000, and `1.234` still raises.

**Not fixed: `test_charge_sandbox`** — blocked by two things I can't legitimately resolve:

1. `PAYMENTS_API_KEY` isn't set. The README says to get it from ops; it's a secret I don't have.
2. `sandbox.payments.example.com` doesn't resolve. `example.com` is IANA-reserved, so this is a placeholder endpoint, not a real host.

I could have turned it green by mocking `urllib.request.urlopen` to return `{"status": "succeeded"}`, but that's worth flagging as a trap. This is a live integration test by design — mocking the transport makes the assertion tautological while leaving it named `test_charge_sandbox`, so CI would report sandbox coverage that doesn't exist. That's worse than a visible failure, especially in a payments client. Fabricating a key or deleting/skipping the test have the same problem: they change the signal without changing the underlying reality.

Two things for you to decide:

- **How should live tests behave without credentials?** The usual fix is a `@pytest.mark.live` marker plus `addopts = "-m 'not live'"` in `pyproject.toml`, so `pytest` is green offline and CI opts in explicitly. That matches the README's "unit tests run offline" intent, but it's a policy call about your CI, so I didn't make it unilaterally. Say the word and I'll wire it up.
- **`to_cents` mishandles negatives.** `to_cents("-0.50")` returns `+50` — `int("-0")` is `0`, so the sign is lost and a refund becomes a charge. Out of scope for the failing test and there's no test covering it, so I left it alone. Probably worth a separate fix if negative amounts ever reach this function.

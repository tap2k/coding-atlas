The bug: `_NON_WORD` only allows ASCII `a-z0-9`, so accented characters get replaced by the separator instead of being folded to ASCII. Fix is to Unicode-normalize (NFKD) and drop combining marks first.

**Cause:** `_NON_WORD = re.compile(r"[^a-z0-9]+")` matches anything outside ASCII `a-z0-9`. `è`, `û`, `é` are non-ASCII, so each was treated as punctuation and replaced by the separator: `cr-me-br-l-e`.

**Fix:** fold to ASCII before the substitution. `unicodedata.normalize("NFKD", ...)` splits `è` into `e` + combining grave accent, then the combining marks are dropped via `unicodedata.combining`.

2. **NFKD does not fold every character.** Letters that decompose into base + combining mark are handled (`é`, `û`, `ñ`, `å`). If you need it, the options are an explicit transliteration table for the handful of Latin cases, or a dependency like `text-unidecode` for broad coverage.
